FIRESET — подготовка к деплою на Vercel

Содержимое
- Статический сайт из HTML-файлов; сборка npm/build не нужна.
- vercel.json: правила trailing slash и базовые HTTP security headers.
- sitemap.xml и robots.txt сохранены.
- Canonical URL и sitemap указывают на https://fireset.site — это корректно, если на Vercel будет подключен именно этот домен.

Как задеплоить
1. Распакуйте архив. В корне проекта должны сразу находиться index.html, vercel.json, robots.txt и sitemap.xml.
2. Импортируйте папку/репозиторий в Vercel как статический проект.
3. Framework Preset: Other. Build Command и Install Command оставьте пустыми; Output Directory — . (корень проекта).
4. После первого деплоя добавьте fireset.site и www-домен в Project → Settings → Domains. Выберите основной домен и настройте редирект второго на основной.
5. Проверьте главную, внутренние страницы, favicon, /robots.txt и /sitemap.xml.

Важные замечания
- В проекте нет package.json и серверной части: для текущей версии это нормально, сайт статический.
- Перевод использует Google Translate и зависит от доступности стороннего сервиса.
- Canonical и sitemap не менялись на домен vercel.app, чтобы не повредить SEO при подключении fireset.site.
- Перед переключением DNS сравните страницы на preview-домене и текущем сайте. Если домен fireset.site ещё не подключён к этому проекту, canonical всё равно будет ссылаться на fireset.site.
